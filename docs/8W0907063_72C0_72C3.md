## 1. Overview & Architectural Differences vs. `4N0907063` / `8W1907063` (v3.x)

The earlier B9/4M generation **`8W0907063`** uses a completely different binary layout from **`4N0907063` / `8W1907063` (v3.x)** (`4N0` on C8/D5/Q7/Q8, `8W1` on B9/FY facelift):
- **4-byte header** (ASCII version only, e.g., `"B911"`, `"Q711"`, `"B903"`, `"B904"`) instead of `4N0`'s 20-byte header (`ver + 12B id + 4B struct_ver`).
- **Trailing 4-byte Big-Endian IEEE 802.3 CRC-32** (`zlib.crc32(data[:-4])`) verified **203 / 203 (100%)**.
- **16-bit Zone Bitmasks (`uint16 BE`, 15 logical zones `0..14`)** instead of `4N0`'s 80-bit `NodeMask80` (10 bytes).
- **Direct 3-byte RGB values** embedded inline in `72C0`, `72C1`, and `72C3` instead of `4N0`'s 50-entry indexed `LinColors` lookup.
- **56 × 4-byte Slave Descriptor Records** in `72C2` instead of `4N0`'s 48-byte `LinAddress[48]` 3×16 bus array.

## 3. Dataset `72C1` — `ALM Szenario` (`254 B`, active `0xBE` = `190 B` @ `0x400197EC`)

Every scenario step is an **8-byte `ScenarioStep8`** record using **16-bit logical zone bitmasks (`uint16 BE`)** and direct inline RGBs:

```c
typedef struct {
    uint16_t mask_grp1;   // BE uint16: Primary / OFF or Surface zone bitmask (bits 0..14)
    uint16_t mask_grp2;   // BE uint16: Secondary / ON or Contour zone bitmask (bits 0..14)
    uint16_t mask_aux;    // BE uint16: Auxiliary / Fade-OFF zone bitmask (bits 0..14)
    uint8_t  brightness;  // Target brightness % (0..100; e.g. 20, 75, 100)
    uint8_t  fade_time;   // Ramp / fade duration (e.g. 0x06 = 600ms)
} ScenarioStep8;
```
